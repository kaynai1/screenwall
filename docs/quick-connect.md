# 连接码连接（ID + 密码）

不登录账号，输入对方设备的 9 位连接码和密码就能连过去。这是 CrossDesk / GT 远程那类
「本机 ID + 密码」的交互，连接仍然经自建服务器中转（服务器负责把两端牵到一起并转发
画面），不需要公网 IP，也不需要在同一局域网。

## 怎么用

被控端（要被人连的那台）：

1. 正常登录账号（连接码挂在账号的设备记录上）。
2. 打开 设置 → 安全 → 连接码连接：
   - 设置一个连接密码（至少 6 位，只在本机明文保存）；
   - 打开「允许连接码连接」。
3. 把「本机连接码」（9 位数字）和密码告诉对方。换码会立刻让旧码失效。
   连接码和密码都直接显示在 **工作台（屏幕墙）页面顶部**，不需要进设置。

主控端（去连的那台）：

1. 登录页切到「连接码连接」。
2. 填服务器地址、9 位连接码、密码，点「连接」。
3. 直接进入远程桌面，不需要账号，也不会在对方机器上弹「允许控制」确认框。

## 一次性连接链接

不想让对方输码时，用链接：被控端在工作台顶部点「生成链接」，复制后发给对方。
对方点开链接 → 网页上点「在 ScreenWall 中打开」→ 客户端被唤起并直接连入。

- 链接形如 `http://服务器/l/<随机令牌>`，**10 分钟有效、只能使用一次**。
- 链接本身就是凭据，所以不设密码；服务器只存令牌的 SHA256。
- 落地页只负责唤起客户端，不消费令牌；真正换令牌由客户端调
  `POST /api/v1/connect-link/use`，且只有设备在线时才会消费成功
  （设备离线返回 409，链接仍然可用）。
- 也能直接粘贴链接到登录页的「连接码或连接链接」输入框，跳过网页那一步。
- 已登录账号时打开链接会先弹确认框：链接会话是匿名的，会退出当前账号。
- 需要在被控端开启「允许连接码连接」；关闭后签发会被拒绝（403）。
- 协议注册：安装包（perMachine）写入 `HKLM\Software\Classes\screenwall`，
  卸载时删除。客户端是单实例的，第二次启动会把链接转发给已有窗口。

## 安全模型

- **密码就是授权凭证**。开启「允许连接码连接」意味着知道密码的人可以直接控制本机，
  这是它和「同账号设备」模式最大的区别（后者每次都要在被控端点允许）。不想这样
  就关掉开关，或换一个密码。
- 密码用 Argon2 哈希存在服务器的设备记录里；明文只在被控端本机的 `client.json`。
- 服务器只给主控端一个 **15 分钟、只能打开这一台设备** 的受限令牌：
  - 不能调 `/api/v1/devices`、`/api/v1/me` 等账号接口（返回 403）；
  - `/ws/view` 的设备列表只含目标那一台，打开别的设备会被拒绝。
- 受限令牌不写盘：主控端进程重启后失效，需要重新输码。
- 限流：
  - 每个 IP 每分钟最多 10 次连接尝试（`[limits] quick_connects_per_minute`）；
  - 同一连接码 + IP 连续输错 5 次，锁定 60 秒；
  - 连接码不存在、密码错误、开关关闭都返回同一类提示，避免探测哪些连接码存在。
- 被控端仍受「允许被控」总开关约束；关闭后连接码也连不进来。

## 和另外两种连接方式的区别

| | 账号登录 | 连接码 | 一次性链接 | 局域网直连 |
| --- | --- | --- | --- | --- |
| 需要账号 | 是 | 主控端不需要 | 不需要 | 不需要 |
| 需要服务器 | 是 | 是（只做撮合与中转） | 是 | 不需要 |
| 跨网段 | 是 | 是 | 是 | 否 |
| 被控端确认 | 每次弹窗 | 密码正确即进入 | 链接有效即进入 | 每次弹窗 |
| 凭据有效期 | 30 天令牌 | 15 分钟 | 10 分钟且单次 | 长期令牌 + 每次确认 |

## 排障

- **提示「连接码或密码不正确」**：确认开关已打开、密码没有改过、输入的是 9 位数字
  （空格和短横线会自动忽略）。
- **提示「这台设备当前不在线」**：被控端客户端必须正在运行并已登录账号。
- **提示「这台设备没有开启连接码连接」**：对方关了开关，或还没设置密码。
- **频繁提示限流**：等一分钟再试；如果确实在被人猜密码，让对方换一个连接码。
- **点链接没反应**：客户端没装或协议未注册（旧版本装的包）。装最新安装包后重试，
  或把链接直接粘到登录页的「连接码或连接链接」输入框。
- **提示「连接链接已失效」**：超过 10 分钟、已经被用过，或对方换了连接码。
  让对方重新生成一条。
