# M0 实现说明

> 状态：骨架完成，编译与测试通过（2026-11-23）
> 对应里程碑：M0 / 2026-11-23
> 方向调整：下一阶段从「手动 Token + IP」改为「单安装包 + 账号登录 + 服务器中转」，见 [server.md](server.md)

## 已实现

- Cargo workspace：`crates/proto`、`crates/agent`、`crates/client`
- 协议层：全部消息类型的 serde 定义、24 字节二进制帧编解码、错误码，附单元测试
- Agent：
  - 读取/生成 `%APPDATA%\ScreenWall\agent.toml`（设备名、端口、Token、允许被控）
  - 首次运行生成自签证书，启动 WSS 服务（默认 `0.0.0.0:47900`）
  - hello 握手、Token 校验（恒定时间比较）、协议版本与「允许被控」检查
  - 欢迎消息、显示器列表、每 5 秒状态推送、ping/pong
  - 显示器枚举（user32，主显示器排第一）
- 客户端：
  - Tauri 2 应用，Rust 侧负责 TCP/TLS/WebSocket 与重连（指数退避，最长 30 秒）
  - 共享 Token 与设备列表持久化到 `%APPDATA%\ScreenWall\client.json`
  - 每 5 秒 ping，测量 RTT；状态与分辨率实时反映到界面
  - React 界面：Token 设置、添加/移除设备、在线状态卡片、空状态、错误提示
- 验收测试：`crates/agent/tests/handshake.rs`
  - 正确 Token → welcome + display.list + status
  - 错误 Token → 错误码 4001 或对应关闭码
- WebCodecs 检测页：`ui/public/webcodecs.html`

## 环境

- Rust 1.100（`stable-x86_64-pc-windows-msvc`）
- Visual Studio 2022 Build Tools：C++ 工作负载 + Windows 11 SDK
- Node 24 + npm 11
- 依赖镜像：rustup / crates.io 使用 rsproxy.cn，npm 使用 npmmirror

> 在 Git Bash 里直接跑 `cargo` 会撞上 `/usr/bin/link`（coreutils），必须在 MSVC 环境下运行。
> 用 `scripts\cargo.bat` 包一层，它会调用 `vcvars64.bat` 并补齐 PATH。

## 运行

### 1. 被控端

```powershell
scripts\cargo.bat run -p screenwall-agent
```

首次运行会在 `%APPDATA%\ScreenWall\` 生成配置和证书，并在控制台打印：

```
Token  : <base64>
指纹   : AA:BB:...
监听   : 0.0.0.0:47900
```

把 Token 复制到客户端。防火墙弹出时允许访问（端口 47900）；注意 Windows 自动生成的规则 profile 实测是 `Public`，不一定是「专用网络」，排障见 [direct.md](direct.md)「连不上怎么查」。

### 2. 客户端

```powershell
cd D:\screenwall\ui
npm install
npm run dev
```

另开一个终端：

```powershell
cd D:\screenwall
scripts\cargo.bat run -p screenwall-client
```

首次启动后在界面里粘贴 Token、添加设备地址（`192.168.x.x`、`100.x.x.x` 或 `host:端口`）。

> 也可以装 `tauri-cli` 后直接 `cargo tauri dev`，它会自动带起 Vite。

### 3. WebCodecs 检测

开发模式下打开 `http://localhost:1420/webcodecs.html`，或用 Edge 直接打开 `ui/public/webcodecs.html`。

## 验收标准

- 客户端卡片显示「已连接」，每 5 秒刷新 RTT
- 显示 Agent 上报的显示器分辨率与版本
- 关掉 Agent 后卡片转为「等待重连」，重新启动后自动恢复
- 错误 Token 显示鉴权失败原因

## 调试

- Agent 日志级别：`$env:RUST_LOG="debug"; scripts\cargo.bat run -p screenwall-agent`
- 配置与证书：`%APPDATA%\ScreenWall\`
- 客户端配置：`%APPDATA%\ScreenWall\client.json`
- 测试：`scripts\cargo.bat test -p screenwall-proto -p screenwall-agent`

## M0 的已知取舍

- 证书不做固定，只打印指纹；局域网可信环境兜底，中转链路由服务器 TLS 保护
- 当前客户端仍是「Token + 设备地址」界面，M1 会替换成账号登录和设备列表
- 当前 Agent 监听入站端口；M1 改为主动连接中转服务器，入站监听只保留给局域网直连
- 没有托盘和开机自启，需要手动运行
- 状态里的 CPU、码率固定为 0，M2 接上采集后再填（2026-11-24 已补：`crates/agent/src/stats.rs` 用 `GetSystemTimes` 差分报整机 CPU，按会话出流字节数差分报 kbps）
- 设备地址只支持主机名/IPv4 + 可选端口
