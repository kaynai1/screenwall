# M1 账号与中转实现说明

> 状态：服务器、Agent 中转、客户端登录界面已完成，待本机人工登录验收
> 对应里程碑：M1 / 2026-11-23
> 规格：[server.md](server.md)

## 已实现

### 服务器（`crates/server`）

- SQLite 存储：账号、令牌、设备
- 密码 Argon2id 哈希；令牌 32 字节随机、数据库只存 SHA-256
- HTTP API：
  - `POST /api/v1/register`
  - `POST /api/v1/login`
  - `GET /api/v1/me`
  - `POST /api/v1/logout`
  - `GET /api/v1/devices`
  - `PATCH /api/v1/devices/{id}`
  - `DELETE /api/v1/devices/{id}`
  - `GET /healthz`
- WebSocket：
  - `/ws/device`：被控端长连接，设备上线/离线
  - `/ws/view`：主控端长连接，设备列表推送
  - 会话打开、关闭、拒绝
  - 8 字节会话帧按 `session` 双向转发
- CLI：
  - `screenwall-server run`
  - `screenwall-server user add|list|reset`
  - `screenwall-server token revoke`

### Agent 中转（`crates/agent/src/cloud.rs`）

- 使用账号令牌主动连接 `wss://<server>/ws/device`，断线指数退避
- 收到 `open` 后建立会话：等待 `hello`、返回 `welcome` / `display.list` / `status`
- `ping` / `pong`、输入消息占位、视频订阅返回「M0 尚未实现画面编码」
- 局域网直连继续保留，两种模式可以同时运行

### 客户端（`crates/client` + `ui`）

- 登录 / 注册界面：服务器地址、用户名、密码
- 登录成功保存 `serverUrl`、账号令牌、用户名、设备 ID
- 主控连接自动重连，接收设备列表与在线状态
- 本机同时作为被控端连接服务器，其他设备能看到本机
- 设备卡片：在线状态、最后上线时间、可控制开关、本机标记
- 退出登录会吊销令牌并断开连接

## 本机运行

### 1. 启动服务器

复制开发配置：

```powershell
copy D:\screenwall\server.dev.toml D:\screenwall\server.toml
```

启动：

```powershell
cd D:\screenwall
scripts\cargo.bat run -p screenwall-server -- run --config server.toml
```

`server.dev.toml` 开启了公开注册，仅用于本机开发。正式部署请关闭注册，用
`screenwall-server user add <用户名>` 创建账号。

### 2. 启动客户端

```powershell
cd D:\screenwall\ui
npm install
npm run dev
```

另开终端：

```powershell
cd D:\screenwall
scripts\cargo.bat run -p screenwall-client
```

在界面里填：

- 服务器地址：`http://127.0.0.1:8787`
- 用户名 / 密码：注册或使用已有账号

登录后，本机会自动作为被控端上线。另一台电脑装同一个客户端、登录同一账号，
就能在列表里互相看到。

### 3. 当前能看到什么

- 设备在线 / 离线
- 最后上线时间、操作系统、版本
- 本机标记
- 服务器连接状态

画面、屏幕墙和键鼠控制还没接入，卡片上标注为 M2。

## 已知取舍

- 中转服务器能看到会话明文；自用服务器可信，后续加端到端密钥。
- 账号令牌保存在 `%APPDATA%\ScreenWall\client.json`，尚未使用 Windows 凭据管理器。
- 客户端目前只连接服务器中转，局域网直连入口还没接到界面。
- 关闭客户端窗口会同时停止被控端；托盘常驻在 M6 接入。
- 服务器默认只监听 `127.0.0.1:8787`，公网部署需要 Caddy/Nginx 提供 TLS。
