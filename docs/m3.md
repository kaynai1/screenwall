# M3 · 键鼠控制、超级屏与显示器保活

M3 在 M2「能看到画面」的基础上，补上了「能操作」和「多屏/关屏」两块能力：

- 被控端接收主控端的鼠标、滚轮、键盘事件，通过 Win32 `SendInput` 注入；
- 被控端采集整块 Windows 虚拟桌面（超级屏），多显示器按系统排列拼成一张画面；
- 采集期间阻止显示器休眠，并实测了显示器电源关闭时 GDI 采集仍然有效。

> 2026-11-24 更新：控制端现在可以按显示器切换（`video.sub.display`），默认主屏，`4294967295` 表示本文的「超级屏」拼接。输入坐标随所选显示器映射；选中单块屏时 DXGI 按输出复制，拼接仍走 GDI。

## 1. 输入链路

```text
控制页鼠标/键盘事件
  → api.sendControlInput(clientToken, events)
  → Tauri 命令 send_control_input
  → Message::Input(InputBatch)
  → 8 字节会话帧（TunnelKind::Json）
  → 服务器按会话转发
  → agent handle_text
  → input::inject
  → SendInput
```

协议沿用 `crates/proto/src/messages.rs` 中已有的定义，`InputEvent` 使用 `tag = "k"`、camelCase：

| 形态 | 含义 |
| --- | --- |
| `{"k":"move","abs":[x,y]}` | 绝对移动，`x/y` 为虚拟桌面归一化坐标 0..1 |
| `{"k":"move","rel":[dx,dy]}` | 相对移动 |
| `{"k":"button","button":"left","down":true,"abs":[x,y]}` | 鼠标按键，按下时可带定位 |
| `{"k":"wheel","delta":[0,120]}` | 滚轮，120 为一格；正值向上 |
| `{"k":"key","scan":30,"down":true,"ext":false}` | 键盘扫描码 |
| `{"k":"text","text":"a"}` | Unicode 文本（协议已支持，前端暂未使用） |
| `{"k":"releaseAll"}` | 释放所有已按下的键和鼠标键 |

### 坐标

- 主控端按画面的 `object-fit: contain` 实际显示区域换算，扣掉上下或左右黑边，得到 0..1。
- 被控端用 `MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` 映射到整个虚拟桌面，因此副屏也能点到；虚拟桌面指标无效时退回主屏。
- 单显示器时虚拟桌面等于主屏，与 M2 行为一致。

### 键盘

- 前端维护 `KeyboardEvent.code → Windows 扫描码` 映射，覆盖字母、数字、F1–F12、方向键、编辑键区、修饰键、标点、小键盘等。
- 方向键、编辑键区、右 Ctrl/Alt、Win 键、`NumpadEnter` 等带 `ext: true`。
- 长按由浏览器的 `event.repeat` 驱动重复 keydown；被控端不做额外连发（`SendInput` 本身不会产生系统按键重复）。
- 浏览器 `F11` 保留给本应用；`Esc` 在全屏时只退出全屏，非全屏时正常发到远端。

### 远程光标

早期 GDI 采集的画面不包含系统光标，控制页曾在输入层之上绘制一个本地光标指示（`.ctrl-remote-cursor`，mint 色圆点 + 光晕）。这个本地叠加层已经删除：被控端现在会把系统光标直接合成进视频帧——GDI 路径用 `GetCursorInfo` + `DrawIconEx`（`crates/agent/src/capture.rs` 的 `GdiCapturer::draw_cursor`），DXGI 路径用 `GetFramePointerShape`，是否绘制由 `VideoSub.cursor` 决定，聚焦流订阅 `cursor: true`（屏幕墙缩略图不画）。见 [design.md](design.md) 5.2 的现状说明。

因为画面里的光标就是被控端真实的系统光标，前端不再需要（也不应该）自己画一层，否则会出现两层光标重影。`scripts/verify-m3.js` 的第 5 项因此改成断言「控制页的舞台内没有本地光标叠加层」，详见第 4 节。

### 安全与清理

- 主控端命令校验 `client_token`，旧页面无法向新会话注入。
- 单批最多 256 条事件，被控端再次限制并丢弃超限部分。
- 失焦、窗口 blur、页面隐藏、关闭开关、离开实时画面、会话断开、组件卸载都会发送 `releaseAll`。
- 被控端在会话结束、采集线程退出时也会释放自己按下过的所有键，避免「卡键」。

## 2. 超级屏（虚拟桌面采集）

`capture.rs` 不再只抓主屏，而是读取：

- `SM_XVIRTUALSCREEN` / `SM_YVIRTUALSCREEN`：虚拟桌面左上角（副屏在左侧时为负）；
- `SM_CXVIRTUALSCREEN` / `SM_CYVIRTUALSCREEN`：整块虚拟桌面宽高。

`StretchBlt` 的源矩形使用这组坐标，目标按 `max_width` 等比缩放：

- `out_w = min(src_w, max_width)`，不放大；
- `out_h = round(src_h * out_w / src_w)`，至少 1 像素；
- 非矩形排列（上下错位）时，包围盒中的空档会显示为桌面背景/黑色，这是虚拟桌面拼接的固有表现。

显示器热插拔不会让已经启动的采集线程自动换尺寸，需要重新订阅画面（退出再进入控制页）。

## 3. 显示器保活与关屏

采集线程启动时调用：

```text
SetThreadExecutionState(ES_CONTINUOUS | ES_DISPLAY_REQUIRED | ES_SYSTEM_REQUIRED)
```

线程退出时恢复为 `ES_CONTINUOUS`。作用是只要有人正在看画面，被控端不会因为电源计划的空闲计时自动关屏/睡眠。

实测（本机 1920×1080，脚本 `scripts/test-monitor-off.ps1`）：广播 `SC_MONITORPOWER` 关闭显示器，等待 3 秒后重新抓屏：

```text
baseline:  mean=152.47 stddev=99.86
while off: mean=152.56 stddev=99.85
mean pixel diff: 0.41 / 255
RESULT: PASS
```

说明显示器电源关闭、但主机仍运行时，Windows 仍在合成桌面，GDI 采集可用。

完全没接显示器（无头）/ 笔记本合盖的情况需要虚拟显示器驱动（IDD）或 HDMI 假负载，详见 `docs/display.md`。

## 4. 验收

前置：服务器、Vite、客户端（CDP 9222）都在运行，且已登录。

```bash
node scripts/verify-m2.js   # 画面链路
node scripts/verify-m3.js   # 键鼠注入 + 光标叠加层检查
```

`verify-m3.js` 会：

1. 确认控制页在实时画面、输入层存在、键鼠开关已开；
2. 派发 50%/50%、75%/50% 两个鼠标位置，读取 Windows 真实光标坐标并比较；
3. 派发 `KeyA` 的 keydown/keyup，用 `GetAsyncKeyState(0x41)` 检查按下与释放；
4. 派发 `Escape`，用 `GetAsyncKeyState(0x1B)` 检查按下与释放；
5. 断言控制页的舞台（`.ctrl-screen`）内没有本地光标叠加层：`.ctrl-remote-cursor` 不存在，且舞台内任何 class / id 含 `cursor` 的元素也不存在。这一项验证的是「不会出现两层光标」——真实光标由被控端合成在视频帧里，前端 DOM 无法断言它画出来了，只能保证本地没有再叠一层。

> 第 2 项的期望落点按主屏（`display 0`）计算。如果控制页切到了副屏或「全部屏幕」，被控端的输入映射区域随之改变，期望值不再成立，请先切回默认的主显示器再跑。

本机自测时，被控端注入会移动同一个物理光标，光标落到捕获层上会再次触发 `mousemove`，形成只在本机自测中出现的回授。脚本在测量期间临时给输入层设置 `pointer-events: none` 来隔离这个回路；跨机使用时不存在该问题。

最近一次结果（本地光标叠加层还在时）：

```text
page: live=true | inputLayer=true | hint=键鼠控制已开启
move 50%/50%: drift=0,2
move 75%/50%: drift=1,2
remote cursor: found=true visible=true pointerEvents=none
key A: pressed=true | released=true
key Esc: pressed=true | released=true
checks: pointer=OK | keyboard=OK | esc=OK | cursor=OK
RESULT: PASS
```

> 上面的输出是**当时**（本地光标指示还在、脚本还在检查 `.ctrl-remote-cursor` 是否显示）的结果，只作历史记录。脚本第 5 项已改成断言本地光标叠加层不存在，输出行也从 `remote cursor:` 变成 `cursor overlay: stage=... frameReady=... localOverlay=none ...`，检查名从 `cursor` 变成 `cursor-overlay`。改完脚本后尚未在运行中的客户端上重跑，新格式的实测输出待补。

## 5. 当前限制

- 画面是 MJPEG，超宽超级屏和 10 FPS 下带宽较高，暂无自适应降码率。
- 没有远端光标身份区分：画面里画的是被控端的系统光标，被控端如果有第二个鼠标/触控板，主控端无法区分来源（本地光标叠加层已删除，见上文「远程光标」）。
- `text` / 输入法尚未接入，中文输入依赖远端输入法和键盘扫描码。
- UAC 安全桌面、锁屏界面无法注入（Windows 限制）。
- 不同 DPI 缩放的多显示器可能让画面坐标与实际像素不完全线性。
- 剪贴板同步、文件拖拽、音频仍未接入。
- 显示器热插拔需要重新订阅画面才能刷新采集尺寸。
