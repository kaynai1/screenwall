# M2 真实画面实现说明

> 状态：单台控制画面链路已实现，待实机验收（2026-11-24）
> 对应里程碑：M2 / 2026-11-24
> 规格：[protocol.md](protocol.md)、[server.md](server.md)

## 已实现

### 被控端采集与编码（`crates/agent/src/capture.rs`）

- Windows GDI 采集主显示器：用 `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 取屏幕尺寸，
  `GetDC(0)` 取得屏幕 DC，再建一块 32 位 DIB。
- `StretchBlt` 抓屏时直接缩放到目标尺寸：输出宽度取屏幕宽度与 `maxWidth` 的较小值，
  默认请求 1280；高度按比例计算。缩放使用 `HALFTONE` 模式。
  `CAPTUREBLT` 失败时自动退回普通 `SRCCOPY`。
- DIB 的 BGRA 像素逐像素转成 RGB，再用 `image` crate 编码 JPEG，默认质量 65。
- 单帧受服务器 1 MiB 中转上限约束。JPEG 超过上限时先用质量 40 重编一次，
  仍然超限的帧直接丢弃并记日志。
- 采集运行在独立线程，按订阅帧率节流；会话结束、`CaptureHandle` 被丢弃时线程退出。
- 参数范围：`fps` 1–15、`maxWidth` 320–1920、`quality` 30–80。
  客户端控制页使用 10 FPS / 1280 / 65。
- 当前只支持主显示器（`display = 0`）和 `mjpeg` 编码，其它请求分别返回
  4103（显示器不存在）、4104（编码器不可用）。

### 协议与中转

- 复用现有 24 字节媒体帧头（`crates/proto/src/frame.rs`）：
  `type=1` 表示视频，`streamId` 为订阅 `id`，`seq` 逐帧递增，
  `tsUs` 为采集线程启动后的微秒数，`codec=1` 表示 JPEG。
  MJPEG 每帧都是完整图像，因此关键帧标志位每帧置 1。
- 复用现有 8 字节会话帧头（`crates/proto/src/cloud.rs`）：
  JSON 消息 `kind=1`，媒体帧 `kind=2`，`session` 为服务器分配的会话号。
- 链路为主控端 → 服务器 `/ws/view` → 被控端 `/ws/device`。
  服务器按 `session` 双向转发，单帧负载默认上限 1 MiB（`max_frame_bytes`），
  超限帧被丢弃。
- 会话内仍每 5 秒推送一次 `status`，`ping` / `pong` 生效；
  `video.unsub` 可停止采集；`video.keyframe` 对 MJPEG 无操作。
- 画面只经过服务器转发，服务器不落盘。

### 客户端（`crates/client/src/main.rs`）

- 新增 Tauri 命令：
  - `start_control(deviceId, clientToken)`：向服务器发送 `open`，等待 `open.ok`
    （8 秒超时），随后发送 `hello` 和 `video.sub`（focus、10 fps、最大宽 1280、
    JPEG 质量 65、MJPEG）。
  - `stop_control(clientToken)`：发送 `close` 并结束本地会话。`clientToken`
    不匹配时忽略，避免旧页面的清理动作关掉新会话。
- 同一时间只保留一个远程会话；新的 `start_control` 会先结束旧会话。
- 新增事件：
  - `control-state`：`opening` / `streaming` / `closed` / `error`。
    `streaming` 由 `video.sub.ok` 触发，携带实际宽度、高度和帧率。
  - `control-frame`：每帧的 `seq`、采集时间戳、宽高、帧率、字节数，
    以及 `data:image/jpeg;base64,…` 形式的 `dataUrl`；同时带 `clientToken`。
- 收到的二进制帧按会话号、视频类型和 JPEG 编码过滤；
  超过 2 MiB 的异常帧直接丢弃，避免拖慢 WebView。

### 前端（`ui/src/pages/ControlPage.tsx`）

- 进入控制页先订阅 `control-state` / `control-frame`，再调用 `start_control`。
  每次进入生成新的 `clientToken`，旧会话的帧和状态会被忽略。
- 收到首帧前继续显示 `DesktopPreview` 预览；首帧到达后切换为真实 `<img>`，
  后续帧直接写 `img.src`，不触发 React 逐帧重渲染。
- 每秒统计一次：FPS 为这一秒收到的帧数，码率为字节数 × 8 / 10^6 Mbps，
  分辨率来自 `video.sub.ok`。顶部工具栏与右侧「会话统计」显示这三项。
- 12 秒内没有收到首帧、被控端返回错误或会话断开时，显示错误提示和「重新连接」。
- 退出页面或切换设备会调用 `stop_control` 结束会话。

## 会话流程

```
viewer（客户端）              服务器                    agent（被控端）
  │ ── open ───────────────▶ │ ── open ───────────────▶ │
  │ ◀──────────── open.ok ── │ ◀──────────── open.ok ── │
  │ ── hello ──────────────▶ │ ── hello ──────────────▶ │
  │ ◀─ welcome ───────────── │ ◀─ welcome ───────────── │
  │ ◀─ display.list ──────── │ ◀─ display.list ──────── │
  │ ◀─ status（每 5 秒） ──── │ ◀─ status（每 5 秒） ──── │
  │ ── video.sub ──────────▶ │ ── video.sub ──────────▶ │
  │ ◀─ video.sub.ok ──────── │ ◀─ video.sub.ok ──────── │
  │ ◀══ 连续二进制视频帧 ════ │ ◀══ 连续二进制视频帧 ════ │
  │ ── close ──────────────▶ │ ── close ──────────────▶ │
```

`hello` 仍按协议带 `token` 字段，中转模式下由账号令牌鉴权，该字段留空。

## 参数

| 项 | 值 |
|---|---|
| 采集 | Windows GDI，主显示器 |
| 缩放 | `StretchBlt` + `HALFTONE`，最大宽度 1280 |
| 编码 | JPEG，质量 65（超限回退 40） |
| 帧率 | 默认 10 FPS（可调 1–15） |
| 帧格式 | MJPEG 全帧 + 24 字节媒体帧头 |
| 单帧上限 | 1 MiB（服务器 `max_frame_bytes`） |
| 传输 | 服务器中转，`/ws/view` + `/ws/device` |

## 本机验收

### 1. 启动服务器

```powershell
cd D:\screenwall
copy server.dev.toml server.toml
scripts\cargo.bat run -p screenwall-server -- run --config server.toml
```

### 2. 启动前端开发服务器

```powershell
cd D:\screenwall\ui
npm run dev
```

### 3. 启动客户端

```powershell
cd D:\screenwall
scripts\cargo.bat run -p screenwall-client
```

### 4. 登录并打开设备

在客户端登录同一账号。想验证跨机画面，可在另一台电脑装同一个客户端并登录同一账号。
登录后点击屏幕墙里任意在线设备，进入单台控制页。

预期结果：

- 先从预览画面切换到真实画面，画面左下角标记变为「实时画面」。
- 顶部显示真实 FPS（约 10）、码率和分辨率（宽度不超过 1280）。
- 右侧「会话统计」显示 MJPEG 编码；离开页面后，对端采集线程停止。

## 当前限制

- 只采集主显示器；控制页的显示器 1/2/3 切换仍是界面占位。
- MJPEG 全帧传输，未做 H.264 / WebCodecs，码率随画面内容变化。
- 键鼠注入未接入；页面上的键鼠、剪贴板、声音开关，以及截图、快捷键、
  重启/关机等操作仍是演示。
- 屏幕墙卡片仍是 `DesktopPreview` 预览，还没有缩略流。
- 局域网直连暂未接入画面，当前只走服务器中转。
- GDI 在部分硬件覆盖层（全屏独占游戏、部分视频播放）、UAC 安全桌面和登录界面
  可能黑屏或采集不到。
- 会话延迟尚未测量，控制页延迟显示「—」；连接质量按 FPS 粗估。
- 画面经服务器明文中转，正式使用仍需 HTTPS。
- 本次没有新增采集与图像处理的单元测试，画面链路以实机验收为准。
